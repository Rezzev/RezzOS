# Руководство по контрибуции в RezzOS (CONTRIBUTING.md)

Привет! Спасибо, что решили помочь в развитии **RezzOS** — легковесного учебного дистрибутива Linux на базе BusyBox, ядра Linux LTS и runit. Мы рады любым улучшениям: от исправления опечаток в документации до оптимизации пакетного менеджера и доработки графического окружения.

Перед тем как отправить свой первый Pull Request (PR), пожалуйста, ознакомьтесь с этим руководством.

---

## 🛠️ Как можно помочь проекту?

Вы можете внести вклад в несколько ключевых направлений:
1. **Разработка пакетного менеджера (`pkg` / `rezzinstall`):** Оптимизация Shell-скриптов, добавление обработки зависимостей, ускорение установки.
2. **Создание рецептов (Сборка ПО):** Добавление новых скриптов сборки популярных CLI/GUI-программ в репозиторий пакетов.
3. **Оптимизация инициализации (runit):** Написание легковесных сервисов и скриптов запуска для демонов.
4. **Улучшение GUI:** Тюнинг оконного менеджера (JWM), добавление полезных скриптов автоматизации графической среды.
5. **Документация:** Написание гайдов по сборке ISO, установке дистрибутива на реальное железо и настройке окружения.

## 🚀 Процесс отправки изменений (Git Workflow)

1. **Форкните репозиторий:** Сделайте Fork проекта [semen88pochuev-eng/RezzOS](https://github.com/semen88pochuev-eng/RezzOS) в свой аккаунт.
2. **Создайте ветку:** Создайте новую ветку для вашей фичи или исправления:
   ```bash
   git checkout -b feature/название-фичи
   # или для исправления багов:
   git checkout -b fix/описание-бага
   ```
3. **Внесите изменения:** Пишите чистый, документированный код. Если вы правите Shell-скрипты, следуйте правилам оформления (см. раздел ниже).
4. **Закоммитьте изменения:** Пишите понятные сообщения к коммитам на русском или английском языке:
   ```bash
   git commit -m "feat(pkg): добавлена автоматическая очистка кэша после установки"
   ```
5. **Отправьте ветку на GitHub:**
   ```bash
   git push origin feature/название-фичи
   ```
6. **Создайте Pull Request:** Откройте PR из вашей ветки в ветку `main` основного репозитория RezzOS.

## 📐 Стандарты кода

Поскольку проект ориентирован на легковесность и минимализм, мы придерживаемся следующих правил:

### Shell-скрипты (sh / bash)
* Используйте POSIX-совместимый синтаксис везде, где это возможно, чтобы код оставался совместим с `busybox sh`.
* Всегда проверяйте возвращаемые значения критических команд (`cd`, `mkdir`) или используйте `set -e` там, где это уместно.
* Кавычьте переменные во избежание проблем с пробелами: `"$VARIABLE"`.
* Код должен быть читаемым: используйте отступы в 4 пробела или 1 таб (придерживайтесь стиля изменяемого файла).

### Системный код (C)
* Код должен компилироваться без предупреждений с флагами `-Wall -Wextra`.
* Избегайте утечек памяти и всегда проверяйте результаты системных вызовов (`malloc`, `open` и др.).
* Форматируйте код в едином стиле (рекомендуется стиль K&R или GNU, используемый в кодовой базе).

## 🐛 Сообщения о багах и обратная связь

Если вы нашли ошибку, но не знаете, как её исправить:
1. Проверьте раздел **Issues** на GitHub — возможно, эту проблему уже решают.
2. Если бага там нет, создайте новый Issue.
3. Подробно опишите:
   * Какую версию ядра/образа вы используете.
   * Шаги для воспроизведения багов.
   * Ожидаемый результат и то, что произошло на самом деле (желательно прикрепить логи или скриншот ошибки).
